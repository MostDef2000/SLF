# #348 — implementation plan / risk and quality

**Risk LOW-MEDIUM:** the etalon block is additive UI over an existing, guarded engine chain; the only mutation path is a user-initiated strict bridge apply that reuses the proven v11 preflight/rollback machinery. Main risks: (1) accidental automatic application — mitigated by `autoApply: false`, button-only trigger, and a layer that never touches `result.action`; (2) double/stale apply — mitigated by a token state machine (`idle→applying→applied|failed_rolled_back|failed_unverified`) and re-render invalidation; (3) data drift between source tables and mirror — mitigated by a deterministic sync tool with `--check`; (4) matcher misfiring on engine-derived signals — mitigated by a merged-tag-pool design that is documented and smoke-tested, with defaults d1/b1 and explicit `insufficientData` reporting.

1. Data first: embed the work-order etalon tables verbatim in `dave56-etalon-data.js` (IIFE, `window.SLFDave56EtalonData`), including word maps, domain ranges, lane words and calibration. No logic, no DOM.
2. Mapping: `dave56-etalon-mapping.js` resolves words to domain ordinals; slash pairs resolve conservatively (min ordinal on the defensive axis — matches all three work-order examples) with the aggressive alternate available (`conservative:false`); lanes from lane words; priority omission rules («все направления», ambiguous pairs, «по силе команд»).
3. Layer: `dave56-etalon-layer.js` wraps `CurrentActionHintEngine.run` outermost, installs only under `SLFActivePresetRegistry.suiteVersion === 'slf_tactic_suite_561_v11'`, merges tag sources (context/snapshot/moment signals/last coach context), matches situations first-match-wins, resolves scenarios with fixed precedence and the minute-60 s2 gate, computes delta vs current tactic, and assigns `result.etalon` only.
4. UI: extend `strategy-data-task-a-ui-extension.js` with the etalon block (labels, words, lanes, notes, confidence) inserted after the «Действие» line, plus the apply button state machine, click delegation, stale-token and already-applied handling.
5. Plumbing: `STATE.etalonRecommendation`/`etalonApplyStatus` in `src/core/config.js`; register the three modules in `src/app/bundle-order.json` after `moment-drift-stabilizer.js` (before `ui-layer.js`) with audit entries and `expectedModuleCount` 89.
6. Integrity: `tools/sync-dave56-etalon.mjs` extracts the data module in a vm and regenerates/validates `data/tactics/dave56-etalon-v1.json` (invariants: 24 situations, 6 scenarios, ordinals in-domain; `--check` exit 1 on drift).
7. Documentation: provenance note in `dave-engine-knowledge.js` (data-only), etalon application policy in `contracts/branches/strategy-data-recommendations.md`, this spec set.
8. Verification: bundle-order audit, sync `--check`, preset inventory, bridge and fallback tests, `node --check` on all touched files, and a 7-case vm smoke of the full engine chain (scratch under `/tmp`, not the repo).

**Correct-course:** if the etalon layer detects anything other than the v11 registry, it stays dormant (no UI, no wrapper effect). If a slash pair contains an unresolvable word, the resolvable word is used; a pair with no resolvable words reports `insufficientData` instead of guessing. If the bridge reports `rollback_unverified`, the button stays disabled pending a fresh hint render.

**Tests:** P0 conservative/alternate ordinal resolution for every pair class, scenario precedence and minute gates, caps, priority-lane mapping, insufficient-data defaults, zero automatic apply; P1 full-chain vm smoke including `result.action` non-mutation and stale-token state machine; P2 existing suite (bundle-order, inventory, bridge, fallback, sync `--check`). Performance impact is nil (pure synchronous data lookup per hint render).
