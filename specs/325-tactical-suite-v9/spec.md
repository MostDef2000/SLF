# Spec: Tactical Suite v9 (no-implicit-fallback hold-current contract)

Issue: MostDef2000/SLF#325 (parent #252 — audit comment 6017616745, verdict NOT_READY_FOR_EVIDENCE_RANKING)
Status: Approved implementation (orders R1–R4 implemented; R5 documentation)
Base: c5ca7de7a475d986cd601e0635369313ec5fb34a

## Problem

The parent audit (#252) verdict **NOT_READY_FOR_EVIDENCE_RANKING** rests on four proven defect classes, all present at base `c5ca7de7`:

1. **Implicit fallback contamination.** Nine production read sites silently injected a hardcoded preset when no valid decision existed. The dominant site — `enrich()`'s replace semantics combined with the policy's Arteta default — contaminated **13 of 26** fallbackApplied-labelled telemetry rows: a hold situation was recorded as if a preset had been recommended and/or applied.
2. **Registry/inventory drift.** `data/tactics/active-preset-inventory-v2.json` no longer matched the active registry: `presetCount` 11 vs 10, **15 field-level drifts**, and stale `nearestPairs`. There was no generator and no CI gate binding the inventory to the registry.
3. **Telemetry single-writer violation.** `enrich()` REPLACED `tacticTelemetry` instead of merging, so `recommendedPreset` written by the direction policy at decision time was dropped before effects were scored.
4. **Evidence hook absent.** The ranking formula had no bounded evidence slot, so `#252` could not define what a future evidence adjustment would even attach to.

## Required behavior

- **Registry v9.** `window.SLFActivePresetRegistry` carries `suiteVersion 'slf_tactic_suite_561_v9'`, `recommendationSchema 'slf_rule_decision_v9_tactical_suite'`, `fallbackPolicy '5.61-tactical-suite-v9-hold-current'`, `inventorySchema 'slf_active_preset_inventory_v3'`, exactly 10 active presets, 10 situations, 14 `controlFields`, a `roleContracts` map for every active preset with `fallbackEligible: false`, and a reserved `evidenceAdjustment()` that stays a bounded noop (`return 0`). v9 control deltas: `Pep_BoxControl_bal2` build_fast/dribble/shot 2→1, `Conte_WingbackWidth_bal4` cross 5→4, `Simeone_LowBlock_def5` build_fast 2→1, `Bielsa_ChaosPress_att5` cross 5→4. Formations are unchanged.
- **Policy v9.** `tactic-preset-direction-policy.js` VERSION `'5.61-tactical-suite-v9.0'`, installs only on a registry whose `suiteVersion` equals a hardcoded `EXPECTED_SUITE` constant (mixed-stack guard). `choose()` returns a hold decision (`name:null, hold:true, fallbackReason:'no_eligible_candidate'`) when no eligible candidate exists; `runTacticalSuiteV9` writes a `hold_current` action (`preset:null`, `ruleId:'suite_v9_hold_current'`, `guardType:'hold_current'`); `selectSuiteV9` returns hold `{name:null, progressionAction:'hold_current', fallbackReason:'invalid_preset'|'no_decision'}`; `preferredPreset` returns `null` for unknown situations. Score parts are exactly `{rulePrior, contextFit, riskAdjustment, boundedEvidenceAdjustment}`.
- **Fallback elimination at every decision read site.** `cah-runtime-context` keeps `selected`/`action.preset` null-safe (no `candidates.find(Arteta)`, no Arteta string default); `cah-decision-core` renders a hold text row instead of a preset name; `re-plan-engine` uses a null-hold plan row and a registry-safe `selectRawPreset` wrapper (null when the registry is present and the raw id is not active); `current-action-hint-engine` carries exactly the 10 active ids in `ACTIVE_PRESETS` (retired `Compact_Counter_def3` removed; its signature kept in `TACTIC_SIGNATURES` marked `legacy_retired` for detection only) and reads the schema from the registry; `tactical-lab-v1` derives `productionIds` from the registry.
- **Telemetry contract.** `event-tracker` gains `resolveRecommendationState()` (states: `recommended_and_applied`, `recommended_not_applied`, `manual_override`, `fallback_hold`, `lab_override`; `unknown_legacy` is a read-time-only classification for pre-v9 rows and is never written by the client). `enrich()` MERGES into prior `tacticTelemetry` (prior wins on non-null values) and stamps registry `suiteVersion`/`recommendationSchema`; the stale `'active_presets_v2_bold_policy_v3'` artifact and the `|| 'bold'` riskAppetite default are removed in favor of `registry.defaultRiskAppetite || 'standard'`. `buildPresetEffect` writes 10 recommendation fields at the effect root and inside `tacticContext`; `savePresetEvent` rows carry `applicationSource 'preset_apply'` plus `recommendedPreset`/`actualPreset`/`recommendationState`.
- **Canonical inventory artifact.** `tools/sync-active-preset-inventory.mjs` (`--check` default / `--write`) loads the registry in a vm sandbox, validates registry invariants (count, retired absence, contract controls equality, situation coverage, `fallbackEligible === false`), and compares/writes `data/tactics/active-preset-inventory-v3.json` byte-deterministically (2-space JSON, trailing newline, no timestamps). The diversity test additionally shells out to `sync --check`.
- **Regression coverage.** New plain-process node tests `test-tactic-fallback-hold-current.mjs` and `test-tactic-transition-graph.mjs`; updated `test-tactical-situation-diversity.mjs` (v9 identity pins, roleContracts block, 14-field control table, sync --check) and `test-tactic-telemetry-envelope.mjs` (the four application-state scenarios + enrich MERGE); all wired into `quality-integration.yml`: the `runtime-tactics` job executes `test-tactic-telemetry-envelope.mjs`, `test-tactical-situation-diversity.mjs`, `test-tactic-fallback-hold-current.mjs`, `test-tactic-transition-graph.mjs` and `sync-active-preset-inventory.mjs --check`, while the `static-contract-security` job executes `test-tactical-situation-diversity.mjs` and `sync-active-preset-inventory.mjs --check`; syntax checks are split the same way — `node --check` covers `test-tactic-fallback-hold-current.mjs`, `test-tactic-transition-graph.mjs` and `sync-active-preset-inventory.mjs` in both jobs, `test-tactical-situation-diversity.mjs` in `static-contract-security`, and `test-tactic-telemetry-envelope.mjs` in `runtime-tactics`.

## Non-functional requirements

- **Byte-deterministic inventory artifact.** Same registry bytes → same inventory bytes; no timestamps; `--check` compares both the parsed document and the raw bytes.
- **Null-safety at every decision read site.** No decision read site may substitute a preset literal when the decision is a hold; verified per site by `test-tactic-fallback-hold-current.mjs` (hold branch through the real closure path in an empty-active registry sandbox, `preferredPreset` null paths, `toPlanRows` hold text, and a static source guard banning Arteta fallback literals in the policy).
- **No release of evidence ranking.** `evidenceAdjustment()` stays a noop and `boundedEvidenceAdjustment` stays 0; no Bayesian or champion ranking ships until a clean v9 cohort is accumulated (#252 follow-up).
- **Cohort separation via libraryVersion.** `libraryVersion 'slf_tactic_suite_561_v9'` and `recommendationSchema 'slf_rule_decision_v9_tactical_suite'` separate v9 telemetry from the untouched v8 legacy cohort; pre-v9 rows are never rewritten.
- **Manual safety flags untouched.** `data/tactics/tactic-evaluation-contract-v2.json` is not modified; `safety.clientDoesNotAutoTrain`, `safety.clientDoesNotAutoApply`, `safety.tacticApplicationRemainsManual`, `safety.promotionRequiresHumanApproval` all remain `true`; policy `autoApply:false`.
- **Test suite runtime within existing CI budget.** The 4 new/updated node tests are plain-process (`node:assert` + `node:vm`, no browser, no network) and complete in milliseconds-to-seconds; CI adds only `node --check` syntax gates and direct executions inside the existing jobs — no new jobs, no new workflow.

## Documented deviations

- **riskAppetite default `'bold'` → registry default.** v8 fell back to the literal `'bold'` when no appetite was readable; v9 falls back to `registry.defaultRiskAppetite` (`'standard'`). This changes observable telemetry for rows that previously defaulted to bold and is intentional: the appetite default is registry-owned, not engine-owned.
- **`Arteta_Control433_bal3` controls deliberately unchanged.** The v9 redesign of the baseline preset is semantic — it stops being a fallback identity (nothing injects it anymore) — not a numeric perturbation. Retuning its controls would have invalidated the v8↔v9 comparability of the stable_control role for no proven benefit.
- **STEP static mirror in the transition test.** The policy keeps `STEP` module-local and exposes only `shortestStep()`; `test-tactic-transition-graph.mjs` therefore carries a static mirror of the graph and validates the live graph through `shortestStep()` behavior (adjacency, no extra edges, active-set containment, dynamic connectivity) rather than through direct access to the closure.
- **`lab_override` is defensive-only.** Tactical Lab activations bypass `savePresetEvent` (they apply through the bridge), so the `lab_override` branch of `resolveRecommendationState` guards against future/indirect lab-sourced rows rather than a currently firing path.
- **`unknown_legacy` read-time only.** The client never writes the state; it exists so read-time audits can classify pre-v9 rows without mutating stored history.
